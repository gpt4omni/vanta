# Vanta 0.35.0: first published release, Flatpak remote, and GPU ETC2 decoding

This is Vanta's first published GitHub release and the first build on the
hosted Flatpak `stable` remote:

```sh
flatpak remote-add --if-not-exists vanta \
    https://gpt4omni.github.io/vanta/vanta.flatpakrepo
flatpak install vanta io.github.gpt4omni.Vanta
```

## What you can do now

- **GPU compute ETC2/EAC texture decoding on drivers without native ETC2.**
  On GPUs that lack Vulkan `textureCompressionETC2` (such as NVIDIA), Vanta now
  decodes all seven ETC2/EAC formats on the GPU through a Vulkan 1.0 compute
  shader into pooled `DEVICE_LOCAL` scratch buffers before copying into the
  destination texture, rather than taking a CPU snapshot, hashing compressed
  bytes, and blocking `vkQueueSubmit` on CPU worker threads. In isolated
  1024x1024 microbenchmarks on an NVIDIA GeForce GTX 1080 Ti (driver
  `580.178.04`), GPU compute decode ran 12.5x to 24.7x faster than serial CPU
  decode (0.136 to 0.272 ms including submit and wait idle) and matched CPU
  output bit for bit across all seven formats. `VANTA_NO_GPU_ETC_DECODE=1`
  forces the CPU fallback for comparison; the fallback itself now pools staging
  and descriptor pools, prefers cached host memory, and avoids Write-Combined
  readback stalls.
- **Much less per-event input, JNI, and main-thread overhead.** High-polling-rate
  mouse motion no longer reallocates Cairo/Wayland window regions on unchanged
  geometry, no longer leaks JNI local references or re-scans the JNI class table
  on every event, and no longer triggers duplicate zero-delta keepalive floods
  while movement keys are held. Locked Wayland relative-pointer deltas are
  coalesced per dispatch batch, `ALooper` idle backoff uses single-syscall
  `epoll_pwait2` so input wakes it immediately, and Roblox now receives real
  host RAM in `DeviceParams` instead of 0 MB.

## What is still broken

**In-game frame rates and stutter percentiles on this build are INFERRED, not
measured in a live Roblox session.** Every change here passed the full test
suite, hardware Vulkan compute verification, and isolated microbenchmarks, but
no live game was launched for this release. If you see missing or corrupted
textures on NVIDIA, test with `VANTA_NO_GPU_ETC_DECODE=1` and report the
difference.

**The Flatpak remote is currently unsigned.** `vanta.flatpakrepo` has no GPG
key yet, so Flatpak installs with `gpg-verify=false` until a signing key is
configured.

**Video decoded through Android's `AImageReader` may not play.** Vanta reports
that path unsupported so Roblox 2.746+ starts; if an in-game video stays blank,
include any `[media] AImageReader_newWithUsage` lines from the log.

**Signed-in startup freezes and early startup crashes** reported against 0.34.0
([#92](https://github.com/gpt4omni/vanta/issues/92),
[#109](https://github.com/gpt4omni/vanta/issues/109)) remain open for reports;
voice chat is still experimental and passkey sign-in does not work inside the
WebKitGTK window.

## Also in this release

- **Lower runtime contention across audio, logging, I/O, and workers.**
  `ZSTD_trace_*` hooks bind directly to a no-op override, stub counters are
  lock-free, filtered Android logs drop before `vsnprintf` and write
  non-error lines asynchronously, `SharedPreferences::apply()` flushes off the
  caller thread, PipeWire microphone capture uses a pre-allocated ring buffer
  with zero allocations on the real-time audio callback thread, `AssetManager`
  caches reads behind an `RwLock` with an 8 KiB read-ahead buffer, battery
  sysfs polling runs off the GTK main thread, and global game-log polling is
  throttled to 250 ms.
- **High-refresh display pacing and worker fast paths.** Under `MAILBOX`
  present mode with Display refresh, Vanta targets 1.5x refresh on monitors
  above 60 Hz, and runtime worker waits avoid unnecessary condvar allocation.
- **ThinLTO release builds.** Release binaries now compile with `lto = "thin"`
  and `codegen-units = 1`.
